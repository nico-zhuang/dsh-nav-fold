# 活跃会话自定义色标 · 第一阶段设计

## 范围与现状

已获用户确认：第一阶段只增加一个可保存、复用和编辑的自定义色标；最近使用颜色与外部拖入是第二阶段或更后续，不在本次实现。v0.4.14 的六格（无色、青蓝、钴蓝、靛蓝、雾紫、银灰）、原有键盘 2×3 导航及色标语义都不变。开发仅在 `feat/activity-custom-color-phase1` 分支进行，不升级已安装插件、不修改正式版说明或发布包。

## 交互

六格之下单列「自定义颜色…」入口。没有保存颜色时点此打开小型独立选色对话框；有保存颜色时显示颜色圆点＋「使用自定义颜色」，旁边独立「编辑」入口。选色对话框使用浏览器原生 `input[type=color]` 调出当前系统可用选色器，同时提供可粘贴 HEX 文本输入、3px 细条的亮/暗背景预览、取消和确定按钮。选色期间不写 Host，不改变会话；仅按确定且颜色为严格六位 `#RRGGBB` 时一次性保存全局色槽并将该颜色应用于本行。无效输入禁用确认、保留草稿与明确错误提示；取消/Escape 不保存并将焦点还给该行整理按钮。保存失败时给出错误，不显示伪成功；若 Host 快照未变可直接重试。若保存过程中 Host 快照被替换（即使偏好原文相同），保留已输入草稿但禁用确定，说明需关闭后在当前配置下重新打开，不能将旧草稿自动重试到可能已切换的 profile。

点击已保存的自定义色圆点将这个颜色复制应用到当前会话；对当前行点击同色可清除该行色标。再次编辑色槽时，确认只会更改保存的色槽和当前正在编辑的会话；以前选过旧颜色的其他会话保留当时的 HEX 值，不发生隐式批量换色。该行原有的顶部固定、Quiet 等偏好不能丢失。六格快捷选择、无色清除仍照旧。

## 数据与安全

继续使用 Host profile 的现有 `activityPreferences` volatile 字符串，不引入浏览器专属 localStorage，也不升级 `version:1`，从而保持旧版数据可读。文档增加可选 `customColor: '#RRGGBB'`，每个选用自定义色的会话在 `sessions[id].color` 写入实际 HEX 而不是全局色槽引用；本轮编辑与本行着色作为同一次 Host 文档写入，沿用现有保存队列、版本切换/写入失败回滚与大小上限。读取时只接受五个已知预设键或严格六位 HEX，拒绝 CSS 注入、非字符串和无效长度；规范化为大写 HEX。读取旧版无 `customColor` 的文档继续保持原状；写旧偏好时须保留已保存的色槽。旧版程序若重写含新字段的文档不承诺保留未识别的自定义色，但原五色和排序偏好不得因此失效。Host 当前公开的 `form.set(field,value)` 未暴露可验证的 profile ID／预期版本 CAS／取消机制；如果相同原文的 profile 在异步写入已经发出后切换，客户端无法证明 Host 不会把已发出的写入落到新 profile。该竞态是安装／发布前的安全门槛，不得把 UI 的保存前身份检查冒充完整跨 profile 保证。

自定义 HEX 同时在深浅主题中显示用户实际选择值；对话框同时预览浅/深背景以避免 3px 色条不可辨，不悄悄改变用户色值。选色控件的具体视觉样式需继承既有菜单、Modal、Button 规范；可聚焦、键盘可到达且有中文/英文标签。

## 验收

测试覆盖旧 Host v1 偏好、非法 HEX 防注入、无色/五色原菜单和键盘导航、取消/无效输入不落盘、确定后持久化/重新挂载、复用、编辑不影响其他已着色会话、写入拒绝与跨 profile 时不泄漏草稿、两种主题预览及焦点返回。Node/jsdom 回归为自动化证据；只有在独立可访问的真实 DSH 界面执行后才可称实时 GUI 验收。用户未授权安装、推送、发布或替换现行 v0.4.14。
