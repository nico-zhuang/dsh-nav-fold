# Fold 导航设置与同事去品牌插件整合设计

状态：用户 2026-11-06 明确确认“按方案做，更新上线”；此前同意的是推送功能分支，不覆盖 `main`、不发布正式 Release。本设计沿用 `feat/fold-remote-navigation` 隔离工作树和 0.4.7-preview.5 回滚包。

## 目标与使用路径

1. Fold 插件设置页有单独的“启用会话导航”开关、明确的保存反馈及一段短引导：先开启工作区／活动／收藏三栏，再到 **DSH 设置 → 快捷键** 找到“会话导航 / Navigate sessions”自行设置入口组合键；如使用小米遥控器及「无线麦」，将进入列表按键映射到这个组合键，并核查 DSH 已注册命令及其他插件私有键盘监听的冲突。Fold 不改遥控器和「无线麦」映射，也不预设组合键。导航箭头、确认、Esc 的既有行为不变。
2. `navigationEnabled` 是 Fold Host Config 的独立、持久布尔值，默认 `true`，使先前已打开三栏并已在 DSH 快捷键中设好入口的用户升级后继续可用。有效导航条件是**三栏已保存开启且会话导航开关已保存开启**；三栏关闭时设置页提示其前置条件，不错误地宣称仅打开导航开关即可启用。关闭导航开关应退出正在进行的导航、释放相关快捷键处理并保留三栏状态和用户自行绑定的快捷键；重新打开后恢复使用原绑定。配置尚未就绪或保存失败时不假装已开启；关停插件会清除监听。
3. 把同事 [stoner-byte/dsh-hide-brand](https://github.com/stoner-byte/dsh-hide-brand) 的浏览器端核心做法（稳定 `logoRow` 类名片段、注入去品牌行样式、注入幂等、loader 生命周期边界）适配整合到 Fold 现有独立 Logo 开关，而不是把同事插件作为常驻依赖或仅称“受启发”。仍只在 macOS 已保存开启 `hideBrandEnabled` 时隐藏 DSH 侧栏顶部纯展示品牌整行；关闭设置、停用 Fold 或卸载时还原。只修改 Fold 自身注入的样式，绝不主动安装／卸载同事插件、清除他人的样式或改动 Windows 上可能含交互控件的行。原先单独启用同事插件时 Fold 无法单独恢复 Logo 的共存限制应如实说明。

## 归属与可见介绍

- 在 README 的新版使用说明中明确写出“收录并适配 **stoner-byte 的 `dsh-hide-brand`** 去品牌实现”，链向上游仓库，同时讲清并非完整包含或依赖上游安装包。不能继续使用“仅借鉴思路、未复制源码”的旧叙述。
- 在插件列表描述与 `THIRD_PARTY_NOTICES.md` 标明上游作者／插件名／MIT 声明及其仓库链接；上游 package.json 声明 MIT，但仓库当时未含独立 LICENSE 文件。为被整合的实现保留 MIT 许可全文；不要编造作者未声明的版权年份。

## 变更边界与验收

- 改动现有 Host Schema、设置页组件、导航设置/注册的生命周期、Logo 样式注入及介绍文案，不新建默认全局快捷键、私有快捷键存储或第二个插件。旧配置缺失新字段时按默认 true 处理；原三栏、Logo 设置值和快捷键映射均保留。
- TDD 覆盖新开关默认／切换／保存失败／缺失 Config／三栏依赖／禁用时停止与重新启用，UI 引导出现及无默认键，Logo 幂等、平台作用域、保存开关和停用清理，原有文件夹与会话遥控回归。
- 出独立 0.4.7-preview.6（不覆盖 .5），全套测试与语法／包内容／校验和核对后本机试装、查询 Host Config 与 Client Slot 并比对安装源码；真实 GUI 和实体遥控器未获直接证据时注明测试局限。仅在确认安装与旧包可回退后推送 `feat/fold-remote-navigation` 到 GitHub，验证远端分支指向；不合并 `main`，不创建正式 Release，不上架插件市场。
