# 活跃整理菜单 · C 紧凑色条设计

## 用户决定与视觉依据

用户 2026-11-11 在 A／B／C 三张可辨真实侧栏语境的合成效果图中明确选择 C（原型 `/tmp/navfold-menu-C-20261111.png`）。选择的是布局而非重新定义颜色或保存行为：保留上方「固定在顶部」「免打扰」及其右侧图标；「色标」小标题下六个现有色标由 2×3 改为同一行；横线下方已保存的自定义颜色与独立的铅笔编辑入口处在一行。中文／英文文案与原有冷色名沿用真实插件，不复制原型中不属于插件的模拟侧栏文字。

## 状态、触点及尺寸

六个预设仍依次为无色、青蓝、钴蓝、靛蓝、雾紫、银灰，均保留有名称的 aria-label/title、`menuitemradio`、当前值的可见边框及真实 Host 预设键。六个独立点击区至少 30×30 CSS px，间距不少于 2px；色条组宽度随内容展开，容许 Host 菜单自动定位与遮盖主内容，但不可裁剪六色及编辑按钮。自定义色槽为空时底行只显示可打开选色对话框的「自定义颜色…」按钮；有值时底行左侧圆点＋「使用自定义颜色」是一个独立点击区，右侧与之有细分隔的 SVG 铅笔为另一个独立可聚焦按钮，accessible name 是「编辑自定义颜色」／`Edit custom color`。两者单独显示 hover/focus-visible，不能让整行点击误打开编辑器。

## 键盘与保存边界

焦点在六色时 Left/Right 按视觉顺序移动（环绕），Home/End 到首尾；Down 到自定义入口，Up 到前一条「免打扰」菜单项；从末色 Tab 到自定义入口，其他色的 Tab 退出格子遵循原 Host 菜单流程；自定义使用与编辑分别可用 Tab 进入，Escape 与 modal 焦点恢复维持既有行为。点击当前相同色仍清除。选色对话框、HEX 校验、亮暗预览、失败重试和 Host v1 数据格式不因菜单排版改变。所有视觉通过实机 QA 菜单深色和必要的亮色/窄侧栏检验；仅有合成效果图不能算真实 GUI 验收。

## 真实 Host 菜单验收（独立 QA profile）

2026-11-11 在 `navfold-qa-20261111` 安装包含 C 改动但未发布的测试包；真实 DSH 菜单深色与模拟系统浅色均为 214 CSS px 宽，色标网格 206 CSS px，无水平滚动，六个 30×30 CSS px 色标和右侧 30×30 CSS px 铅笔均在 Host 菜单边界内。1000px 宽浏览器中的标准侧栏显示菜单不裁剪；实测键盘 Tab 可从「使用自定义颜色」进入独立铅笔；点击铅笔打开 HEX 对话框，取消后焦点返回行内整理按钮，不写入颜色。宽 450px 时 Host 会自动折叠侧栏，未把这种不可见菜单当成窄屏已通过；后续不应宣称验证了覆盖屏幕边缘的弹层场景。真菜单裁切截图仅存本机 `/tmp/navfold-menu-c-real-qa-menu-dark.png`、`/tmp/navfold-menu-c-real-qa-menu-light-1280.png`，不包含真实会话标题；合成原型不能替代它们。

## 发布门槛

C 是新布局，在功能分支实现并回归；不能借用户选 C 推定其豁免既存跨 profile 相同 raw 的在途 Host 写入竞态。未证明 Host.set 按调用时 profile 原子归属或具备 profile-scoped/CAS 写入前，不发布含自定义色的正式版。既有 desktop v0.4.14 本机试用与 v0.4.14 公开 tag 不随本设计文档更改。
